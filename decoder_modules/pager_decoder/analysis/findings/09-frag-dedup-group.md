# Stage 9 & 10 — Fragment reassembly + dedup, and Group messages

## Verdict

The **group-message subsystem (Stage 10) is largely a faithful port** of the C logic: the
capcode range constants (2029568–2029583), the target-cycle computation, and the cycle/frame
expiry ladder all match the C ground truth line-for-line. However the **fragment reassembly and
dedup subsystem (Stage 9) is effectively absent**: the C decoder's 64-slot fragment cache
(`frag_find`/`frag_alloc`/`frag_append`/`frag_expire`, keyed on `(capcode,type,msg_n)`, with
F-sequence tracking, R/M carry-over, wrap-safe frame expiry and partial-output-on-timeout) has
**no counterpart** in C++, and the 32-slot word-level dedup/combine cache (`dedup_check_words`)
is **completely missing**. The only C++ fragment code is `FlexMessageDecoder::processFragment`,
a stub that keys every fragment on a hard-coded `capcode = 0`, discards `type`/`msg_n`, and does
naive string concatenation — it is non-functional and would collide all fragment streams into
one buffer. On the group side, two secondary behaviours are dropped (the GroupDelivering /
2-FIW fragment-delivery timeout, and the slot-reuse teardown), and the capcode-cap comparison is
off by one. The two most eye-catching discrepancies (group-bit `& 0x7F` vs C's `& 0x0f`, and
`GROUP_BITS = 17` vs C's 16) turn out to be **cosmetic**, because phase words are pre-masked to
21 bits (`MESSAGE_BITS_MASK = 0x1FFFFF`) so bits 21–23 read by the wider mask are always zero.

## Sub-parts that MATCH (summary for the task's 6 checks)

1. **Fragment slot count / match key** — ❌ (FRAG-01/02): 64-slot `(capcode,type,msg_n)` cache is absent; C++ uses a capcode-0-keyed stub.
2. **Fragment expiry frame-age arithmetic** — ❌ (FRAG-05): no `& 0x7FF` wrap-safe expiry in C++ at all.
3. **Dedup cache (32 slots, combine-on-retransmission)** — ❌ (FRAG-07): entirely absent.
4. **Group capcode range + group-bit = capcode − MIN** — ✅ MATCH (GRP-06); note the *registration-side* group-bit mask/size mismatch is cosmetic (GRP-03/04).
5. **Group target-cycle/frame computation and expiry** — ✅ MATCH (GRP-07, GRP-09, GRP-10), *except* the delivering-guard (GRP-01) that the ladder depends on.
6. **What C does that C++ drops** — partial-output-on-timeout (FRAG-06), R/M carry-over (FRAG-04), F-sequence gap tracking (FRAG-03), GroupDelivering timeout (GRP-01), slot-reuse teardown (GRP-02), the whole dedup cache (FRAG-07).
