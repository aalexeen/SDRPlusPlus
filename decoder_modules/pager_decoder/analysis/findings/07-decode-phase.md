# Stage 07 — Phase dispatch / word-type decoding (`decode_phase` vs `FlexFrameProcessor`)

## Summary verdict

The C++ port is a **drastic, lossy re-implementation** rather than a faithful line-for-line port
of the ~1200-line C `decode_phase`. The core word-index/dispatch skeleton is present and several
primitives are correct (short-address capcode `aw-0x8000`, group range, BIW offset masks, loop
bounds over 88 words, capcode range check). However the two heaviest pieces — **long-address
capcode computation** and **vector-length extraction for numeric types** — use different algorithms
and will produce wrong output on those message classes. A structural vector-slot alignment bug
appears whenever an idle/uncorrectable address word sits *between* valid addresses, because C
compacts (skips without consuming a vector slot) while C++ maps positionally. Large swaths of C
behavior (BIW2/3/4 date/time/SSID parsing, tone-only detection, dedup/merge, temp-address group
teardown, end-of-VF system-message vector, priority flag, per-word BCH-error gating) are absent in
this function; some are genuinely dropped, some are relocated to `FlexMessageDecoder`/
`FlexGroupHandler`. Rows below distinguish real bugs from relocations and refactors.

| PHASE-01 | 🔴 | demod_flex_next.c:3364-3411 | FlexFrameProcessor.cpp:288-301 | **Long-address detection AND capcode formula are entirely different algorithms.** C detects LA via explicit ranges `LA1 0x000001-0x008000` OR `LA2 0x1F7FFF-0x1FFFFE`, then computes capcode with a 3-way set table (Set 1-2, 1-3/1-4, 2-3/2-4), each with distinct additive constants (`+2068480`, `+2068479`) and factors like `(2097151-w2)*32768`, `(w2-1933312)*32768`, `(w2-1867776)*32768`. C++ uses one legacy "PDW" formula `capcode = ((next_word ^ 0x1FFFFF) << 15) + 2068480 + raw_aiw` with thresholds `raw<0x8001 OR (0x1E0000<raw<0x1F0001) OR raw>0x1F7FFE`. Different LA classification boundaries AND different capcode arithmetic → wrong capcodes for every long address. | Port the C range table and 3-set formula verbatim; drop the single PDW expression and the `LONG_ADDRESS_THRESHOLD_*` constants that encode the old boundaries. |
| PHASE-02 | 🟠 | demod_flex_next.c:3311,3316,3471,4029-4034 | FlexFrameProcessor.cpp:105-107,118,180-181 | **Vector-slot alignment: skip-compaction missing.** C tracks `vec_used` and advances it ONLY for processed pages; when an address word is BCH-uncorrectable (3311) or idle (3316) it `continue`s *without* incrementing `vec_used`, so the next valid address still maps to the next unconsumed vector. ## Confirmed-matching sub-parts (verified equal to C)

- **BIW offset masks** — `address_offset = ((biw>>8)&0x3)+1`, `vector_offset = (biw>>10)&0x3F` (C 3000-3002 == C++ 260-263). ✅
- **BIW idle/all-ones reject** — `biw==0 || (biw&0x1FFFFF)==0x1FFFFF` (C 2994 == C++ 254). ✅
- **`voffset < aoffset` invalid check** (C 3010-3013 == C++ 266-269). ✅
- **Short-address capcode** — `capcode = aw - 0x8000` (C 3363 == C++ 300, `AIW_SHORT_ADDRESS_OFFSET=0x8000`). ✅
- **Loop bounds** — `for i in [aoffset, voffset)` over an 88-word (`PHASE_WORDS`) frame (C 3309 == C++ 102); both cap indices at 88. ✅
- **Capcode valid range** — `0 <= capcode <= 4297068542` (C 3412 == C++ `MAX_CAPCODE=4297068542`, isValidCapcode). ✅
- **Group capcode range** — `2029568..2029583`, group_bit = cap - MIN (C `FLEX_GROUP_ADDR_MIN/MAX` == C++ `GROUP_CAPCODE_MIN/MAX`); GROUP_BITS=16 in C (`MAX-MIN+1`) vs 17 in C++ — C++ is one larger but only ever indexes 0..15, so harmless. ✅ (note the off-by-one in the *constant*, not in use.)
- **Message-type enum values** — C `Flex_PageTypeEnum` (Secure=0…NumberedNumeric=7) numerically equals C++ `MessageType` even though slot 2 is named SHORT_MESSAGE in C vs "Tone" in C++; the `(viw>>4)&0x7` dispatch maps identically. ✅
- **Idle address-word skip** — `aw==0 || (aw&0x1FFFFF)==0x1FFFFF` (C 3316-3320 == C++ 105-107). ✅
- **Order** — BCH decode of all 88 words happens before word parsing on both sides (C 2933-2959 loop, then parse; C++ applyErrorCorrection then extract/loop). ✅ (dedup/merge order N/A in C++ — dedup absent, PHASE-12.)
- **Short-instruction assigned-frame mask** — `(viw>>10)&0x7F` (C 3530 == C++ 335). ✅
