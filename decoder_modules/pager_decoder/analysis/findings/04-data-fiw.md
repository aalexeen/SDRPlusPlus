# Stage 04 — FIW parse, State machine, Phase data collection / deinterleave

## Verdict summary

The FIW bit-field extraction and checksum formula are a **bit-for-bit match** with the C
reference, and the deinterleave index math, phase-buffer shift/load, idle-pattern test and
`IDLE_THRESHOLD` all match exactly. However there are **two 🔴 correctness bugs that break
every 3200 bps mode and the 1600/4FSK (A3) mode**: (1) `FlexDataCollector::baud_rate_` is
initialized to 1600 in the constructor and **never updated** (the only setter,
`setTransmissionMode`, is dead code and the inline assignment is commented out), so the
collector always runs the 1600-baud, no-interleave path even for A2/A4; (2) even at the
correct baud, the non-toggle branch always routes `bit_b` to Phase B, whereas C routes it to
Phase C at 1600 baud — so the second phase of A3 lands in the wrong buffer. A third 🔴/🟠:
`processCompletedFrame` derives cycle/frame from the **uncorrected** raw FIW word, not the
BCH-corrected word C uses, so any FIW error BCH repaired feeds wrong cycle/frame into
fragment/group handling. Separately, `handleSync2State` is a blind symbol-count stub that
discards the C S2 C/inv.C correlation and boundary-correction (in-scope, named in the task),
and the FlexStateMachine State-Pattern classes are dead code (the real dispatch is
`FlexDecoder::handle*State`). FIW field parsing also drops `repeat/roaming/traffic/num_tx`,
which C consumes downstream for subframe retransmission.
